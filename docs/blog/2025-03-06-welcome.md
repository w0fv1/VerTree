“最终版”“最终版修改”“这次真的最终版”，往往不是命名习惯的问题，而是没有合适的位置表达一个文件经历过哪些选择。Vertree 想把这些关系整理得更直观。

<!-- truncate -->

## 从一份反复改稿的文件出发

设计稿、方案、脚本或配置都可能需要保留几个阶段。手动复制容易开始，文件一多却很难看清某一版从哪里来，又向哪个方向修改。Vertree 用版本号、备注和分支把这些关系留在普通文件中。

Git 等工具当然能够跟踪二进制文件，但它们的仓库与协作流程并不总是符合单文件改稿的习惯。Vertree 不是要替代它们，而是为不需要整套代码协作流程的任务提供另一种入口。

## 三个取舍

**文件仍是普通文件。** 不把所有版本锁在专有数据库里，原软件仍能打开；代价是完整副本会占用空间。

**阶段版本与自动记录分开。** 手动备份保留重要节点，监控按变化与间隔创建快照。它不承诺每次保存都生成备份，更不能代替异地备份。

**先看清，再决定。** 版本树帮助确认关系，只读预览帮助确认内容。不同格式的还原能力有边界，精确编辑仍交给原软件。

## 一条持续保留的原则

让每一次迭代都有迹可循，不是承诺永远不会丢失文件，而是尽量让重要节点容易留下、关系容易理解、失败也能明确说明。
