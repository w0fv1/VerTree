# 版本树与分支


版本树回答三个问题：当前文件从哪一版而来、旁边有哪些备选方向、需要回看的文件在哪里。它不是文件内容的自动合并工具。

## 打开与查看

从文件菜单选择“查看文件版本树”，或执行 `vertree "文件路径"`。画布读取同一目录内同逻辑名称的版本文件。拖动、缩放或适配画布查看关系；在外部新增文件后使用刷新重新读取。

![示例版本文件的主线与分支](/img/usage/version-tree-page.png)

## 三个常用动作

**保留当前进度。** 原软件保存后，从当前节点创建备份，可加备注。新文件是独立完整副本，不会自动锁定或改写旧文件。

**尝试另一个方向。** 先预览某个节点，再创建分支，编辑分支生成的新文件。修改旧节点文件本身仍会改变那份磁盘文件的内容。

**找回历史内容。** 预览确认后，用原软件打开或复制历史副本为新稿。开发者 API 另提供恢复操作，覆盖前保留 `before-restore` 版本；不要把 API 说明当作界面中必然存在的按钮。

## 命名与整理

```text
方案.docx                  初始文件，视为 0.0
方案#客户确认.0.1.docx      主线后继
方案#备选方向.0.1-0.0.docx  从 0.1 派生的分支
```

备注用来描述阶段，版本号用来表达关系。优先通过应用修改备注，避免手动引入路径分隔符等非法字符。`auto` 模式发现后继已存在时创建新分支，`next` 模式会报告冲突；它们都不应覆盖已有同名版本。

整理整套历史时，尽量保持同族文件在同一目录。自动快照位于独立目录，不直接加入这里的版本树。命名规则的实现见[版本规则](../tutorial-develop/filetree.md)。

## 树不完整怎么办

检查文件是否被移到其他目录、逻辑名称或扩展名是否变了、父版本是否缺失。重复版本与缺少父节点可能产生诊断，不能只凭画布外观判断磁盘文件不存在。

预览可确认内容，但不保证专有格式的完整还原。需要精确排版或编辑时使用原软件；文件比较的程序接口见[本机 API](../tutorial-develop/local-api.md)。
