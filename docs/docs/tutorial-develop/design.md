# 设计取舍

Vertree 围绕单文件的持续修改设计：保留阶段成果、从旧版本派生方案、在保存过程中自动备份，以及快速查看文件内容。

## 用普通文件副本保留版本

版本文件可以直接由原软件打开，也可以通过资源管理器移动、复制或归档。版本树从同目录文件名中的版本段重建，不依赖专有文件数据库。

代价是每个版本占用一份完整文件的空间。对于大设计稿和媒体素材，应按实际容量决定保留频率；监控备份通过数量上限控制增长，手动阶段版本由用户整理。

## 文件名表达关系

逻辑名称、备注、扩展名和树状版本号组成文件名。这样脱离应用也能辨认版本，但随意修改名称、移动部分版本会改变树的重建结果。格式细节见[版本树设计](filetree.md)。

## 手动备份与监控分工

手动备份用于阶段节点，自动监控用于保存过程中的保护。监控按事件与最小间隔工作，不承诺每次保存都有一份副本，也不会自动替用户判断哪些阶段值得永久保留。

## 预览独立于编辑

Vertree 复用 Office-Viewer 的本地解析能力，预览只读快照；编辑仍交给文件关联的软件。预览不执行宏，不运行文件脚本，不保证完整复现每一种专有格式。

格式支持与版本管理互不绑定。专有文件即使没有预览器，也不因此失去复制备份的价值。

## 按平台提供入口

Windows 右键菜单、macOS Services 和 Linux Files 扩展服务于各自系统的工作方式。底层 CLI 和业务逻辑尽量一致，具体入口与依赖按平台说明，避免把某个平台的功能误当作全平台已有能力。

## 区分本机与局域网服务

预览和自动化 API 只服务本机；局域网分享由用户主动创建临时链接。三个功能分别管理生命周期和访问凭据，打开预览不会顺带暴露分享接口。

## 当前没有承诺的能力

Vertree 不是目录级协作仓库，不提供通用文件合并、云端同步或所有二进制格式的差异比较。下一阶段方向见[后续规划](roadmap.md)。
